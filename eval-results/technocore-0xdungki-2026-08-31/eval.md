# Eval Criteria: offline verification of stored Technocore signatures
**Domain:** build
**Date:** 2026-08-31 WIB

## Quality-gate basis

Fresh official change: Technocore Chat commit `702e8237aecec8c1993c05d20b2a248163bc747d` now retains `sig` on signed room records specifically so readers can re-verify them offline. Current toolkit `verify-receipt` only matches claimed DID, nonce, and text in arbitrary JSON; it does not authenticate the record.

## Pass criteria (ALL must be true)

1. **Reproducibility**
   - [ ] From a clean checkout, `python -m pytest -q` passes.
   - [ ] Focused stored-signature tests are deterministic and network-free.
2. **Demonstrability**
   - [ ] A real Ed25519-signed fixture generated by toolkit code is accepted from stored room JSON.
   - [ ] CLI output includes `signature_verified: true` and the matched sequence.
3. **Negative test**
   - [ ] The focused eval fails on baseline/current code before implementation.
   - [ ] A matching record with tampered text/signature or no `sig` is rejected, not reported as verified.
   - [ ] Reverting/removing the critical signature-verification call makes the focused eval fail; restoring it makes focused and full suites pass.
4. **User-spec match**
   - [ ] Contribution is meaningful DID utility tied to the official stored-signature change, not cosmetic.
   - [ ] Live commit exists in standalone `0xdungki/technocore-did-toolkit` (`fork=false`).
   - [ ] GitHub Actions CI completes successfully.

## Fail criteria (ANY = no-go)

- Matching DID/nonce/text without cryptographic signature verification is accepted as verified.
- Missing historical `sig` is called invalid rather than explicitly not re-verifiable.
- Mocked signature verification or network-dependent tests.
- Cosmetic-only changes, duplicate contribution, failed CI, or second X/GitHub contribution on the same WIB day.

- Include exact command, exit code, stdout tail, criterion verdicts, elapsed time, and live artifact URLs.
